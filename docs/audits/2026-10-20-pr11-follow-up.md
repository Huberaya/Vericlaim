## Écarts reproduits puis corrigés

1. Une file de purge survivait au rollback racine : un commit sans rapport sur la même Session supprimait ensuite l'objet. `after_soft_rollback` distingue désormais la transaction réellement annulée ; `after_transaction_end` couvre aussi `close()`/`invalidate()`.
2. `after_commit` d'un savepoint pouvait vider la file avant le commit racine. La garde vérifie désormais systématiquement `in_nested_transaction()` ; un rollback du savepoint retire uniquement ses actions, pas celles de la transaction parente.
3. Le worker appelle sweep puis retry dans la même transaction. Retry pouvait supprimer les objets des marqueurs tout juste créés et non durables. Les uploads encore dans la file de cette Session sont exclus du retry.
4. Le retry pouvait fermer un registre avant l'expiration du POST présigné. Un rejeu recréait alors un objet sans registre ouvert. Le registre reste maintenant ouvert jusqu'au TTL + délai de grâce déjà utilisé par le sweep (90 s + budget antivirus), sans consommer de tentatives pendant cette attente.
5. Le lecteur clamd acceptait un verdict propre avant une seconde trame arrivant dans un autre `recv`. Hors IDSESSION, la fin de connexion est désormais obligatoire sous le même délai total ; toute donnée supplémentaire, absence de terminaison ou erreur reste indéterminée. Une signature FOUND composée d'espaces n'est plus un verdict infecté exploitable.
6. Une liste S3 mal formée pouvait passer pour une liste vide ; une clé retournée hors du préfixe pouvait être supprimée. L'adaptateur exige maintenant un booléen `IsTruncated` et vérifie toutes les clés de chaque page avant suppression.

Les nouveaux tests ont montré les échecs avant correction (rollback, savepoint, sweep/retry, trames fragmentées, réutilisation après close, listes invalides et fermeture trop précoce du registre). Aucun test supprimé ni désactivé.
